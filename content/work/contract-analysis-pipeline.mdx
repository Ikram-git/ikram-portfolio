## Context

An end-to-end, LLM-powered Solidity smart-contract auditor built at HK PolyU
([smartfortress.tech](https://smartfortress.tech)). Rather than asking a bare LLM
"is this contract safe?", it uses a Retrieval-Augmented Generation (RAG) pipeline
and a vector database to ground vulnerability detection in documented exploit
patterns. I own it front to back — the FastAPI/SQLModel backend on PostgreSQL and
the React/Vite/TypeScript frontend.

## Constraint

Two hard problems. First, **scale**: compiling and extracting bytecode and ABIs
from **18 million** raw smart contracts, then deduplicating identical bytecode
into a curated evaluation set you can actually trust. Second, **trust**: a bare
LLM hallucinates vulnerabilities; for audit you need answers anchored to real,
citable exploit patterns — which is why retrieval beats generation alone here.

## What I built

- A Solidity processing pipeline (solc / py-solc-x) to compile and extract
  bytecode and ABIs from 18M contracts, deduplicating identical bytecode into a
  curated eval set.
- The RAG + vector-database layer that grounds detection in documented exploits.
- The FastAPI/SQLModel backend and the React/Vite/TypeScript frontend
  (Tailwind, shadcn/ui), with Playwright E2E tests and Docker-based deployment.
- Separately, a **React/Next.js frontend for a stablecoin compliance platform** —
  real-time on-chain transaction monitoring, wallet risk scoring and AML alerts
  for illicit-activity exposure.

## Decisions and trade-offs

**Retrieval over fine-tuning.** Grounding detection in a vector store of
documented exploit patterns — rather than fine-tuning a model on them — means the
corpus can be updated the moment a new exploit class appears, with no retraining,
and every finding can point back to the pattern that triggered it. That
citability is the whole point for audit: a fine-tuned model that simply asserts a
verdict is far harder to trust or debug.

**Deduplicating on bytecode.** Across 18M contracts the same compiled bytecode
recurs constantly — proxies, forks, re-deploys. Deduplicating on bytecode rather
than source or address collapses that redundancy into a curated evaluation set
that's cheaper to run and stops near-identical contracts from dominating results.
The cost is a compile-and-extract pass (solc / py-solc-x) across the whole corpus
up front.

## Outcome

The pipeline turns 18M raw contracts into a curated, deduplicated evaluation set,
and the auditor grounds its findings in real exploit patterns rather than a
model's unsupported judgement. Live at
[smartfortress.tech](https://smartfortress.tech).
