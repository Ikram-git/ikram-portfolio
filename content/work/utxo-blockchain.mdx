## Context

A blockchain e-payment system built from first principles in Python — no
frameworks, no forks of existing chains. The goal was to understand what a
cryptocurrency actually is by implementing each layer: accounts and keys,
transactions, blocks, mining, and the network that keeps independent nodes
agreeing on one history.

## What I built

- **Accounts and keys** — account creation generates a public/private key pair
  and a derived address, persisted to the database.
- **UTXO transactions** — transfers spend unspent outputs, signed with the
  sender's private key and verified before entering a block.
- **Mining** — nodes mine pending transactions into blocks; the chain and its
  state live in database storage rather than in memory, so nodes restart
  cleanly.
- **Peer-to-peer network** — multiple nodes run on different ports, exchange
  blocks, and converge by the longest-chain rule: blocks mined on one node
  become visible to the others, and a node that falls behind adopts the longer
  history.
- **CLI console** — a small operator console (`account create`,
  `miner start`, `tx list`, `blockchain list`, `node add/run`) drives the whole
  system, which keeps every protocol step observable.

## Why it matters

Most blockchain work builds *on* a chain. Building the chain itself — the
signature verification, the UTXO bookkeeping, the fork resolution — is what
made later production work on smart-contract analysis and on-chain platforms
feel legible: the primitives underneath were never a black box.
