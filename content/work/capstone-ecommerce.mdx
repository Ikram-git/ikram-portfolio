## Context

My BSc final-year project at HK PolyU: an e-commerce application where checkout
settles in cryptocurrency through Ethereum smart contracts instead of a
traditional payment gateway. Designed and built solo — the Solidity contract, the
React front end, and the Web3.js integration between them, deployed on Firebase.

## Constraint

Putting payment on-chain is harder than it looks from the storefront: a
blockchain transaction is slow, asynchronous, and can fail or be dropped after
the user has clicked "buy". The app has to reconcile that uncertain settlement
with order state, handle wallet connection and rejected or pending transactions
gracefully, and keep the smart contract simple enough to trust with real value.

## What I built

- A Solidity smart contract (`Contract.sol`) handling on-chain payment at
  checkout.
- A React.js storefront with Web3.js wallet connection and transaction flow.
- Firebase hosting/deploy for the front end — still live at
  [food-blocks-23e80.web.app](https://food-blocks-23e80.web.app), with the
  source on [GitHub](https://github.com/Ikram-git/Capstone_Project).

## Decisions and trade-offs

**On-chain settlement vs a payment gateway.** Settling directly on-chain removes
the intermediary and makes each payment independently verifiable, but it pushes
latency, gas and failure handling into the checkout UI and ties the flow to
wallet UX. For a final-year project whose goal was to demonstrate an end-to-end
crypto-payment flow, that on-chain settlement was the point rather than a cost to
engineer away — and building it surfaced exactly where the hard edges of
consumer crypto payments live.
